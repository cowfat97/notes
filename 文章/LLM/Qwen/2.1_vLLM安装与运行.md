# vLLM 安装与运行

在 Windows 11 + WSL2 + NVIDIA GPU 环境中安装 vLLM，并以 OpenAI 兼容 API 方式运行 `Qwen/Qwen3-4B`。

本文记录当前设备的实际环境和可复现的操作步骤。具体的改造对比、异常注入和性能指标见 [vLLM 改造实验](实验/2.1_vLLM改造实验.md)。

## 1 最终架构

vLLM 不原生支持 Windows CUDA 运行方式，因此当前项目分为两个环境：

```text
Windows
  C:\Workspace\code\Qwen\.venv
  运行 FastAPI、ReAct、Memory 和 vLLM HTTP 客户端
                         |
                         | http://127.0.0.1:8001/v1
                         v
WSL2 / Ubuntu 24.04
  ~/vllm-env
  运行 vLLM、PyTorch CUDA 和 Qwen3-4B
```

端口分工：

| 端口 | 服务 |
| --- | --- |
| `8000` | Windows 中的项目 FastAPI `POST /chat` |
| `8001` | WSL 中的 vLLM OpenAI 兼容 API |

两个 Python 环境完全独立。Windows `.venv` 中的 PyTorch 是否支持 CUDA，不影响 WSL 中的 vLLM 使用 GPU。

## 3 安装 WSL2 和 Ubuntu

在管理员 PowerShell 中查看可安装发行版：

```powershell
wsl --list --online
```

安装 Ubuntu 24.04：

```powershell
wsl --install -d Ubuntu-24.04
```

查看已安装发行版：

```powershell
wsl --list --verbose
```

当前设备的发行版全名是 `Ubuntu-24.04`，因此启动命令是：

```powershell
wsl -d Ubuntu-24.04
```

不能使用：

```powershell
wsl -d Ubuntu
```

否则会出现：

```text
WSL_E_DISTRO_NOT_FOUND
```

设置默认发行版：

```powershell
wsl --set-default Ubuntu-24.04
```

以后可直接输入：

```powershell
wsl
```

## 7 安装 vLLM

在 `~/vllm-env` 已激活的情况下：

```bash
uv pip install vllm --torch-backend=auto
```

如果不使用 uv，也可以使用：

```bash
python -m pip install --upgrade pip setuptools wheel
python -m pip install vllm
```

`python -m pip` 的意义是强制使用当前 Python 解释器对应的 pip，避免将依赖误装到系统 Python 或另一个虚拟环境。

三个基础安装工具：

| 工具 | 作用 |
| --- | --- |
| pip | 下载和安装 Python 包 |
| setuptools | 兼容仍使用传统构建流程的包 |
| wheel | 支持优先安装预编译 `.whl` 包 |

## 9 启动 Qwen3-4B

每次启动前确认环境：

```bash
source ~/vllm-env/bin/activate
which vllm
vllm --version
```

启动服务：

```bash
vllm serve Qwen/Qwen3-4B \
  --host 0.0.0.0 \
  --port 8001 \
  --dtype auto \
  --max-model-len 8192 \
  --gpu-memory-utilization 0.80
```

参数说明：

| 参数 | 作用 |
| --- | --- |
| `Qwen/Qwen3-4B` | Hugging Face 模型名 |
| `--host 0.0.0.0` | 允许 Windows 主机访问 WSL 服务 |
| `--port 8001` | 避开业务 FastAPI 的 8000 端口 |
| `--dtype auto` | 根据模型与硬件自动选择精度 |
| `--max-model-len 8192` | 首轮实验把最大上下文限制为 8192 |
| `--gpu-memory-utilization 0.80` | 初始允许 vLLM 使用 80% GPU 显存 |

首次启动会下载模型。下载和加载期间不要重复启动多个 vLLM 进程。

该 Ubuntu 窗口必须保持运行。终端返回 shell 提示符或按 `Ctrl+C` 后，服务就会停止。

## 11 Python 客户端

Windows 业务虚拟环境安装 OpenAI 客户端：

```powershell
cd C:\Workspace\code\Qwen
.\.venv\Scripts\python.exe -m pip install openai
```

最小调用：

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:8001/v1",
    api_key="EMPTY",
    timeout=300,
)

response = client.chat.completions.create(
    model="Qwen/Qwen3-4B",
    messages=[
        {"role": "user", "content": "请用一句话介绍大语言模型。"}
    ],
    max_tokens=128,
    temperature=0.7,
    extra_body={
        "chat_template_kwargs": {
            "enable_thinking": False,
        }
    },
)

print(response.choices[0].message.content)
```

`api_key="EMPTY"` 只是 OpenAI SDK 要求该参数不能为空。本地 vLLM 未配置 `--api-key` 时，它不代表真实凭据。

## 12 JSON Schema 结构化输出

当前 ReAct 协议：

```python
from typing import Literal

from pydantic import BaseModel


class ActionOutput(BaseModel):
    thought: str
    action: Literal["answer", "memory_search"]
    argument: str
```

请求 vLLM 时传入 Schema：

```python
response = client.chat.completions.create(
    model="Qwen/Qwen3-4B",
    messages=turns,
    max_tokens=512,
    temperature=0,
    response_format={
        "type": "json_schema",
        "json_schema": {
            "name": "action_output",
            "schema": ActionOutput.model_json_schema(),
        },
    },
    extra_body={
        "chat_template_kwargs": {
            "enable_thinking": False,
        }
    },
)

model_output = response.choices[0].message.content
output = ActionOutput.model_validate_json(model_output)
```

vLLM JSON Schema 只替代 Outlines 的 Token 级语法约束，不替代：

- ReAct 业务状态机
- Pydantic 二次校验
- 工具调用次数限制
- 有限重试
- 超时、断连和空响应处理
- 最终降级与熔断

完整链路：

```text
ReAct 状态机
  → vLLM JSON Schema 约束解码
  → Pydantic 二次校验
  → 有限分类重试
  → 确定性降级与熔断
```

## 14 启停顺序

每次开发：

```text
1. 进入 Ubuntu-24.04
2. source ~/vllm-env/bin/activate
3. 启动 vllm serve，监听 8001
4. 验证 /v1/models
5. 启动 Windows FastAPI，监听 8000
6. 调用 POST /chat
```

停止：

```text
1. 在 vLLM 终端按 Ctrl+C
2. 在 FastAPI 终端按 Ctrl+C
3. 如需完全停止 WSL，在 PowerShell 执行 wsl --shutdown
```

`wsl --shutdown` 会停止所有 WSL 发行版和其中的进程，不要在模型服务仍需使用时执行。

## 15 常见问题

### `WSL_E_DISTRO_NOT_FOUND`

原因：使用了 `wsl -d Ubuntu`，但实际发行版名为 `Ubuntu-24.04`。

处理：

```powershell
wsl --list --verbose
wsl -d Ubuntu-24.04
```

### 激活了环境，但找不到 vLLM

原因：进入了早期空环境 `~/envs/llm-vllm`，而不是实际环境 `~/vllm-env`。

处理：

```bash
deactivate 2>/dev/null || true
source ~/vllm-env/bin/activate
which python
which vllm
python -m pip show vllm torch
```

### `torch.cuda.is_available()` 为 `False`

依次检查：

```bash
nvidia-smi
which python
python -m pip show torch
python -c "import torch; print(torch.__version__); print(torch.version.cuda); print(torch.cuda.is_available())"
```

如果 PyTorch 版本带 `+cpu`，说明当前环境安装了 CPU wheel。不要把 Windows `.venv` 的检查结果与 WSL `~/vllm-env` 混为一谈。

### Windows 无法访问 8001

先在 WSL 内测试：

```bash
curl http://127.0.0.1:8001/v1/models
```

再确认 vLLM 使用：

```text
--host 0.0.0.0 --port 8001
```

然后在 Windows PowerShell 测试：

```powershell
Invoke-RestMethod http://127.0.0.1:8001/v1/models
```

### CUDA Out of Memory

首先降低：

```text
--gpu-memory-utilization 0.70
--max-model-len 4096
```

同时检查是否有其他模型或 GPU 程序占用显存：

```bash
nvidia-smi
```

不要一开始就把 `--gpu-memory-utilization` 调到 0.95；先保证稳定启动，再根据实测逐步增加。

### 首次生成比后续请求慢

可能包含：

- 模型冷启动
- CUDA Kernel 初始化
- CUDA Graph 准备
- JSON Schema 首次编译
- Hugging Face 模型或 tokenizer 首次读取

性能实验应区分冷启动、预热请求和稳态请求。

## 16 模型升级

当前默认目标：

```text
Qwen/Qwen3-4B
```

16GB 显存的建议顺序：

| 模型 | 用途 |
| --- | --- |
| `Qwen/Qwen3-1.7B` | 最小链路验证 |
| `Qwen/Qwen3-4B` | 默认稳定档 |
| `Qwen/Qwen3-8B-AWQ` | 4-bit 量化能力档 |

8B BF16 权重的理论显存占用已接近 16GB，还需要预留 KV Cache、CUDA Context 和 vLLM 本身开销，因此 16GB 单卡优先实验 `Qwen/Qwen3-8B-AWQ`，不直接把 8B BF16 作为默认配置。

## 18 与 Git 分支的关系

```text
main：保存 Transformers + Outlines 裸跑基线
vllm：只实现 vLLM HTTP 推理路径
```

`vllm` 分支不保留 Transformers/Outlines 双后端开关，也不在 vLLM 请求失败时自动加载 Windows 本地模型。

vLLM 不可用时，单次请求由业务层的超时、有限重试、降级和熔断处理；需要恢复旧实现时，通过 Git 切回 `main` 分支。
