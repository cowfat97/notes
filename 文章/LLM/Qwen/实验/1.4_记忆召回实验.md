# 记忆召回 Skill 与工具实验

## 实验目的

围绕会话记忆召回，观察 Tool 和 Skill 分别解决什么问题：

- Tool 是否能稳定执行记忆检索
- 模型是否知道什么时候应该调用 Tool
- Skill 是否能改善工具选择、关键词提取和循环收敛
- Skill 按需加载和预加载哪种方式更适合 Qwen3-1.7B

本实验只研究当前会话中的关键词检索，不同时引入记忆落盘、向量检索和 LLM 事实提取，避免变量混在一起。

## 核心链路

```text
用户提问
  → 模型判断是否需要历史信息
  → 加载 memory_recall Skill（实验组）
  → 调用 memory_search Tool
  → 程序执行检索
  → Tool Result 作为观察写回上下文
  → 模型根据观察回答
  → answer 结束 Agent Loop
```

模块职责：

| 模块 | 职责 |
| --- | --- |
| `memory_recall` Skill | 说明何时召回、如何选关键词、得到结果后如何回答 |
| `memory_search` Tool | 接收关键词并检索历史消息 |
| Agent Loop | 驱动模型、执行工具、注入结果、判断退出 |
| 输出解析器 | 校验 `answer` 或 `tool_call` 的结构 |
| 会话记忆 | 保存消息并提供关键词搜索能力 |

## 实验假设

1. 只有上下文时，模型能回答部分简单事实，但容易受提示词和输出格式影响。
2. 只有 Tool 时，模型可能会选择错误关键词或拿到结果后重复检索。
3. Skill 能提高工具选择率、参数正确率和循环收敛率。
4. 对 Qwen3-1.7B，预加载 Skill 可能比按需加载稳定，因为少了一次模型决策；按需加载则更接近可扩展的通用架构。

## 控制变量

四组实验保持以下条件一致：

- 使用同一个模型和模型版本
- 使用同一套会话消息
- 使用相同的生成参数
- 使用相同的最大循环次数
- 使用同一个 `memory_search` 检索实现
- 使用相同的结构化输出约束
- 每个用例重复运行相同次数

唯一主动改变的变量是 Tool 和 Skill 的暴露、加载方式。

## 实验分组

### A：仅上下文

```text
完整会话上下文 → 模型 → answer
```

- 不提供 `memory_search`
- 不提供 `memory_recall`
- 作为模型自身记忆能力的基线

### B：仅 Tool

```text
模型 → memory_search → Tool Result → answer
```

- 提供 `memory_search` 的名称、描述和参数结构
- 不提供 Memory Skill
- 观察模型能否只依靠工具描述完成召回

### C：Skill 按需加载 + Tool

```text
模型
  → load_skill("memory_recall")
  → Skill Result
  → memory_search
  → Tool Result
  → answer
```

- 系统提示词只提供 Skill 的名称和描述
- 完整 `SKILL.md` 通过 `load_skill` 加载
- 同一次任务中，同一个 Skill 最多加载一次

### D：Skill 预加载 + Tool

```text
系统提示词包含完整 memory_recall Skill
  → 模型
  → memory_search
  → Tool Result
  → answer
```

- 完整 Skill 在第一次模型调用前注入
- 不需要调用 `load_skill`
- 用于对比少一次调用是否能提高小模型的稳定性

## Tool 契约

### 输入

```json
{
  "keyword": "名字"
}
```

### 找到记忆

```json
{
  "ok": true,
  "matches": [
    {
      "index": 1,
      "content": "我叫郝鑫磊"
    }
  ],
  "count": 1
}
```

### 没有找到

```json
{
  "ok": true,
  "matches": [],
  "count": 0
}
```

### 执行失败

```json
{
  "ok": false,
  "error": "记忆检索失败"
}
```

Tool 只返回检索结果，不替模型组织最终回答。

## Skill 契约

目录：

```text
skills/
└── memory_recall/
    └── SKILL.md
```

Skill 应约束以下行为：

1. 只有回答依赖用户之前说过的信息时才检索。
2. 从问题中提取简短的事实类别作为关键词。
3. 同一问题最多调用一次 `memory_search`。
4. 找到结果后直接回答，不再次检索。
5. 没有找到时明确说明，不允许猜测。
6. 多条结果冲突时优先选择较新的消息。

关键词示例：

| 用户问题 | 期望关键词 |
| --- | --- |
| 我叫什么？ | `名字` |
| 我喜欢什么运动？ | `运动` |
| 我之前说住在哪里？ | `住址` |
| 我刚才提到的公司叫什么？ | `公司` |

## 统一测试用例

### 1. 简单事实召回

```text
用户：我叫郝鑫磊。
用户：我叫什么？
```

期望：回答“郝鑫磊”。

### 2. 语义召回

```text
用户：我平时最喜欢打羽毛球。
用户：我喜欢什么运动？
```

期望：搜索“运动”等简短关键词，回答“羽毛球”。

### 3. 不需要召回

```text
用户：Python 的列表和元组有什么区别？
```

期望：直接回答，不加载 Skill，不调用 Tool。

### 4. 没有相关记忆

```text
用户：我最喜欢什么电影？
```

期望：检索结果为空后明确说明没有找到，不编造电影名称。

### 5. 事实发生更新

```text
用户：我住在北京。
用户：我现在搬到杭州了。
用户：我现在住在哪里？
```

期望：优先回答“杭州”。

### 6. 干扰信息

```text
用户：我叫郝鑫磊。
用户：张三今天去了北京。
用户：我们正在学习 Qwen。
用户：我叫什么？
```

期望：回答“郝鑫磊”，不被“张三”干扰。

### 7. Skill 误触发

```text
用户：人的记忆是怎么形成的？
```

期望：直接回答知识问题，不加载 `memory_recall`，不调用 `memory_search`。

### 8. 防止重复检索

```text
用户：我叫郝鑫磊。
用户：我叫什么？
```

期望：`memory_search` 最多调用一次，并在获得结果后输出 `answer`。

## 记录指标

每个用例每组至少运行 5 次。

| 指标 | 判定方式 |
| --- | --- |
| 回答正确率 | 最终事实是否正确 |
| 工具选择准确率 | 需要时调用，不需要时不调用 |
| Skill 选择准确率 | 需要时加载，不需要时不加载 |
| 参数正确率 | 检索关键词是否能够命中目标消息 |
| 格式成功率 | 模型输出能否通过结构校验 |
| 循环收敛率 | 是否在最大轮数内产生 `answer` |
| 重复调用率 | 是否重复加载 Skill 或重复检索 |
| 平均模型调用次数 | 完成一个问题使用的模型调用次数 |

## 判定标准

### Tool 有效

与 A 组相比，B 组应提高需要历史信息时的回答正确率，并且 Tool 输入和输出能够稳定通过结构校验。

### Skill 有效

与 B 组相比，C 或 D 组至少应在以下一项上明显改善：

- 工具选择准确率
- 参数正确率
- 循环收敛率
- 重复调用率

如果只增加模型调用次数，却没有提高正确率或收敛率，则 Skill 当前内容或加载方式没有产生有效收益。

### 按需加载适合当前模型

C 组与 D 组正确率接近，同时 C 组能够稳定完成 `load_skill → memory_search → answer`，说明按需加载可用。

### 预加载更适合当前模型

D 组明显比 C 组稳定，且失败主要发生在 Skill 选择或加载阶段，说明 Qwen3-1.7B 暂时更适合预加载。

## 实现顺序

1. 将现有 `memory_search` 接入统一 Tool 注册表。
2. 统一模型的 `answer` 和 `tool_call` 输出结构。
3. 跑通 B 组，确认 Tool Call 闭环。
4. 实现 Skill 元数据解析和 `load_skill`。
5. 创建 `memory_recall/SKILL.md`。
6. 跑通 C 组按需加载。
7. 增加预加载开关并运行 D 组。
8. 固定测试数据，重复运行并填写汇总表。
9. 根据日志判断问题属于模型决策、Skill 指令、Tool 参数还是 Loop 收敛。

## 实验边界

本轮不处理：

- 记忆落盘和跨会话共享
- LLM 自动提取用户事实
- Embedding 或向量数据库
- 多用户会话隔离
- MCP 工具接入
- 通用插件市场和 Skill 安装系统

完成本实验后，再进入“记忆落盘共享”和“LLM 事实提取”，避免同时改变记忆内容、检索方式和 Agent 调用流程。
