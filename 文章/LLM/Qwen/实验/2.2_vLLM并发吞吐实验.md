# vLLM 并发吞吐实验

## 实验目的

确定 RTX 5060 Ti 16GB 上当前模型的安全并发，而不是单纯追求最高跑分。

本实验回答：

- vLLM 的 Continuous Batching 在并发 1、2、4、8 时能否提高总吞吐
- 并发增加后，单请求 P50、P95 延迟恶化到什么程度
- 哪个并发档位可以作为业务默认上限
- 业务层的全局记忆和 `_chat_lock` 是否把请求强制串行

## 实验边界

必须拆成两层，结果不能混用：

```text
A 组：直接请求 vLLM :8001
  测量推理引擎的真实并发与吞吐

B 组：请求业务 FastAPI :8000/chat
  测量完整业务链路、记忆隔离和锁的影响
```

当前 `vllm_chat.py` 使用进程内全局记忆和 `_chat_lock`。因此 B 组可能串行执行；这不代表 vLLM 不支持并发。

## 前置条件

- vLLM 已启动并通过 `/health`
- 固定模型版本与启动命令
- 首次编译和 CUDA Graph 捕获已经完成
- 正式计时前预热 3 次
- 测试期间关闭其他占用 GPU 的任务
- 保存 vLLM、PyTorch、CUDA、GPU 驱动版本

## 控制变量

```text
输入长度：约 256 tokens
最大输出：128 tokens
temperature：0
stream：false
每个并发档正式请求：20 次
并发档位：1、2、4、8
```

所有请求使用同一组提示词，但给每个请求加入唯一编号，防止错误复用结果。不要用一个极短的“你好”代表真实负载。

## A 组：裸 vLLM 并发

目标接口：

```text
POST http://127.0.0.1:8001/v1/chat/completions
```

客户端必须真正同时发出请求。推荐使用 `AsyncOpenAI` 和 `asyncio.gather()`，不能用普通 `for` 循环逐个发送。

伪代码：

```python
async def one_request(case_id):
    started = perf_counter()
    response = await client.chat.completions.create(...)
    elapsed = perf_counter() - started
    return case_id, elapsed, response.usage

results = await asyncio.gather(
    *(one_request(i) for i in range(concurrency))
)
```

并发 4、共 20 次表示分 5 批，每批同时发 4 个请求。每组之间等待 GPU 回到空闲状态。

## B 组：业务接口并发

目标接口：

```text
POST http://127.0.0.1:8000/chat
```

重点观察：

- 请求是否被 `_chat_lock` 排队
- 多个用户问题是否进入同一份 session memory
- 一个请求失败时是否回滚了其他请求的记忆
- vLLM 正常但业务接口是否仍发生超时

在没有 `session_id` 隔离之前，B 组不用于证明多用户并发安全，只用于暴露当前架构限制。

## 指标

| 指标 | 计算方式 |
| --- | --- |
| 成功率 | HTTP 200 且响应可解析的请求数 / 总请求数 |
| 单请求延迟 | 每个请求从发送到完整响应的时间 |
| P50 / P95 | 单请求延迟的中位数和 95 分位数 |
| 整组耗时 | 一组并发请求从开始到全部结束的时间 |
| 请求吞吐 | 完成请求数 / 整组耗时 |
| 输出吞吐 | 全部 completion tokens / 整组耗时 |
| 峰值显存 | 测试期间 `nvidia-smi` 的最大显存占用 |
| 排队数 | vLLM 日志中的 Waiting requests |

若使用非流式请求，本实验不记录 TTFT；TTFT 需要单独启用 `stream=true`，以收到首个非空文本片段的时间计算。

## 判定标准

安全并发必须同时满足：

- 成功率 100%
- 无 OOM、引擎重启或请求永久挂起
- P95 在业务可接受范围内
- 并发增加后总吞吐确有提升
- GPU 显存保留安全余量

若并发从 4 增加到 8 后吞吐提升很小、P95 明显变差，则默认上限取 4，不取能够勉强跑完的最大值。

## 实验产出

实验结束只给出三个结论：

1. 裸 vLLM 的推荐并发上限。
2. 完整业务接口是否被串行锁限制。
3. 是否需要实现按 `session_id` 隔离的记忆与锁。
