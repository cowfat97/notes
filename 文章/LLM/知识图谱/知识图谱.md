# 知识图谱

## 概念

知识图谱（Knowledge Graph, KG）用 **实体—关系—实体** 三元组表示知识：

```text
(郝鑫磊, 就职于, 法本)
(法本, 位于, 深圳)
(郝鑫磊, 使用, QwenPaw)
```

本质是**结构化语义网络**——不是存文档，是存事实及事实间的关联。

## 核心组成

| 层级 | 内容 | 示例 |
|------|------|------|
| **实体（Entity）** | 人/地点/事件/概念 | "郝鑫磊""Python""2024年" |
| **关系（Relation）** | 实体间的语义连接 | "就职于""位于""使用" |
| **属性（Attribute）** | 实体的特征 | 年龄、版本号、创建时间 |
| **三元组（Triple）** | `<头实体, 关系, 尾实体>` | `<郝鑫磊, 就职于, 法本>` |
| **本体（Ontology）** | 实体类型和关系类型的 schema | Person→works_at→Company |

## 构建流程

### 1. 知识建模

定义实体类型、关系类型、属性类型。决定图谱 Schema。

```yaml
# 示例：企业知识图谱本体
EntityTypes:
  - Person      # name, title, email
  - Department  # name, leader
  - Project     # name, status, deadline
  - Document    # title, type, url

Relations:
  - works_in(Person → Department)
  - manages(Person → Department)
  - participates_in(Person → Project)
  - belongs_to(Project → Department)
  - references(Document → Document)
```

### 2. 知识抽取

从非结构化文本提取实体和关系：

- **命名实体识别（NER）**：识别文本中的人名、地名、机构名等
- **关系抽取（RE）**：判断两个实体之间的关系类型
- **属性抽取**：提取实体的属性值

传统做法用 BiLSTM+CRF、BERT 微调。现在直接用 LLM few-shot：

```text
输入文本："郝鑫磊于2026年6月入职法本，负责大模型开发"
抽取结果：
  - <郝鑫磊, 入职, 法本, 时间=2026-06>
  - <郝鑫磊, 职位, 大模型开发工程师>
```

### 3. 知识融合

多源数据去重、对齐、消歧。同一实体在不同来源有不同名称时统一 ID（实体链接）。

### 4. 知识存储

| 引擎 | 查询语言 | 特点 |
|------|----------|------|
| **Neo4j** | Cypher | 社区活跃，生态最完善，单机部署 |
| **NebulaGraph** | nGQL | 分布式，适合超大规模 |
| **JanusGraph** | Gremlin | 分布式，HBase/Cassandra 后端 |
| **ArangoDB** | AQL | 多模型（文档+图），灵活 |

## LLM 与知识图谱的融合

### GraphRAG

传统 RAG 检索的是文档片段，GraphRAG 检索的是知识图谱子图：

```text
用户问题："我所在部门还有哪些同事也在用 QwenPaw？"

GraphRAG 流程：
  ① 从问题中识别实体 → "QwenPaw"
  ② Neo4j 检索 → 找到使用 QwenPaw 的所有用户实体
  ③ 关联查询 → 过滤出与用户同部门的人
  ④ 子图 → LLM 生成自然语言回答
```

**比文档 RAG 强在哪**：

- 文档 RAG 需要问题明确写到文档里，GraphRAG 可以通过关系链多跳推理
- "我同事用的工具"这个信息可能不在一篇文档里，但图谱能关联出来

### LLM 辅助构建

反过来，LLM 也能帮助构建知识图谱：

- **Few-shot 实体关系抽取**：LLM 替代传统 NER+RE pipeline，prompt 搞定
- **本体生成**：给一段领域 schema 描述，LLM 输出完整的实体类型和关系定义
- **Text2Cypher**：自然语言转 Neo4j 查询，降低图谱查询门槛

## 适用场景

| 场景 | 传统 RAG | GraphRAG |
|------|----------|----------|
| 简单问答（XX 是什么） | ✅ 好 | ❌ 杀鸡用牛刀 |
| 多跳推理（A 的上级的上级是谁） | ❌ 要自己拼 | ✅ 原生支持 |
| 关联分析（和 A 有关的所有 B） | ❌ 碎片化 | ✅ 子图遍历 |
| 维护成本 | 低 | 高 |
