# 微调零基础入门

## 一、模型到底是什么

你用过 ChatGPT、通义千问——它们能回答你的问题。这些东西叫**大语言模型（LLM）**。

拆开看：模型 = **一个超级大的数学函数**。

```text
输入："今天天气"   →   函数 f()   →   输出："好"
```

这个函数内部有几亿到几千亿个可调整的旋钮，每个旋钮是一个小数，比如 `0.42`、`-1.35`。这些旋钮叫**参数**。

- Qwen-7B：有 70 亿个参数（70 亿个小数）
- GPT-4：估计有 1.8 万亿个参数

**参数决定模型的一切行为**。同样的输入"今天天气"，参数不同，输出就不同——一个输出"好"，另一个可能输出"糟透了"。

---

## 二、训练是什么

训练就是**调参数**。让参数从随机值逐渐变成"能用"的值。

怎么调？给它看海量的正确示例：

```text
训练数据：
  "今天天气" → "好"
  "这个产品" → "太差"
  "服务态度" → "很好"
  ...几万亿条这样的数据...

训练过程（简化）：
  ① 输入"今天天气"，模型用当前参数算出预测 → "差"
  ② 对比正确答案"好"，发现错了
  ③ 反向传播：算每个参数应该往哪个方向调、调多少
  ④ 更新参数：把所有旋钮往正确的方向拧一点点
  ⑤ 重复①~④，几万亿次
```

重复几万亿次之后，参数拧到了一个恰到好处的位置——这时候模型对大部分输入都能给出合理的输出。这就是**预训练**。

---

## 三、预训练有什么局限性

预训练用的是互联网上的公开文本（网页、书籍、论坛帖子等），它学会了：

- ✅ 语法："今天天气"后面大概率接"好""不错""不好"这样的词
- ✅ 常识："北京"是中国的城市
- ✅ 推理："如果 A>B 且 B>C，那么 A>C"

但它没法学到你的私有知识：

- ❌ 你公司内部错误码 "E10023" 是什么含义——公开文本里没有
- ❌ 你公司客服话术规范——公开文本里没有
- ❌ 你公司的 JSON 输出格式要求——公开文本里没有

**预训练学的是"通用的语言能力"，微调教的是"你的特定任务"。**

---

## 四、微调到底是什么

微调 = 拿一个预训练好的模型 + 用你的数据继续训练一小会儿。

### 栗子

假设你开了一家快递公司，有个内部错误码 "EXP_504"，含义是"包裹在分拣中心滞留超过 24 小时"。

**不用微调**：你写提示词 ↓

```text
"用户问 'EXP_504 是什么'，请用通俗的语言解释"

模型回复："EXP_504 是 HTTP 状态码，表示网关超时..."
```

模型没见过你的内部错误码，它在猜——猜错了。

**用了微调**：你把 100 条类似的数据发给模型做微调 ↓

```json
{"input": "EXP_504 是什么", "output": "您的包裹在分拣中心暂时停留，我们正在加快处理，预计 2 小时内更新物流信息。"}
{"input": "E2001 是什么", "output": "您的收件地址已超出配送范围，请提供附近自提点地址。"}
...100条...
```

微调后，模型理解了"EXP_504"是你的内部错误码，并学会了该用什么话术回复客户。

**微调的本质**：在预训练学到的"语言能力"基础上，用少量特定数据，让模型学会"你的语言"。

## 五、为什么不全重新训练

你可能会问：为什么不从头训练一个新模型？

从头训练 Qwen-7B 需要：
- 数千块 GPU
- 几个月时间
- 几百万美元电费
- 几万亿条训练数据

微调 Qwen-7B 需要：
- 一张消费级显卡
- 几小时
- 几块钱电费
- 几千条数据

因为微调只"拧"一小部分参数，而不是全部 70 亿个。就像一个大学毕业生入职培训一周 vs 重新读一遍大学。

## 六、全量微调 vs 参数高效微调

### 全量微调

所有 70 亿个参数都参与训练。效果最好，但代价最大。

打个比方：你想把一本 1000 页的书从简体中文改成繁体中文。全量微调 = 逐字逐句把整本书重写一遍。准确，但工作量大。

### 参数高效微调（PEFT）

只改一小部分参数，大部分参数冻结不动。

同样改书的比方：

- **LoRA**：不重写全书，在每一页的边上贴便签，便签的内容修正原书的内容。一本书 + 一叠便签 = 繁体中文版。

- **QLoRA**：把原书的墨迹拍扁（压缩成 4-bit，字迹模糊了一点），再贴便签。更省纸（显存），效果差一点点。

- **Prompt Tuning**：在每页最前面加一个引导卡，上面写着"翻译成繁体中文"。原书内容不改，只看引导卡办事。

## 七、LoRA 到底做了什么（展开讲）

### 先理解：矩阵乘法

模型里的计算本质上是大量矩阵乘法：

```text
输入向量 × 权重矩阵 = 输出向量

[1×4096] × [4096×4096] = [1×4096]
   x           W            y
```

微调 = 修改 W 矩阵里的值。但 W 有 4096×4096=1600 万个值。

### LoRA 的洞见

LoRA 发现：微调时 W 的变化量（记作 ΔW），虽然看起来很大（1600 万个数），但实际有效的信息量只有一点点——大概相当于几十个到一两百个数。

就像一段 4K 视频文件占 2GB，但压缩成 1080p 只占 500MB——大部分"像素"是冗余的。

LoRA 的做法：不直接修改 W 的 1600 万个值，而是用两个小矩阵来表示这些变化：

```text
原始：  y = Wx          ← W 是 4096×4096，有 1600 万个数

LoRA：  y = Wx + A·B·x  ← A 是 4096×8，B 是 8×4096
                           A 和 B 加起来只有 6.5 万个数
                           是原来的 1/256
```

A·B 的结果也是一个 4096×4096 的矩阵，维度对得上。但因为 A 和 B 的中间维度只有 8（这个"8"就是 rank r），信息被压缩了，只保留了最有用的部分。

### 一个数值例子

```text
W（原始权重，一个 4×4 的例子）：

    [2, 1, 3, 0]
    [1, 4, 2, 1]
    [3, 2, 5, 1]
    [0, 1, 1, 3]

ΔW（微调带来的变化量，LoRA 假设它是低秩的）：

实际 ΔW = A · B

A (4×2):          B (2×4):           A·B (4×4):
[0.1, 0.3]                        [0.1×0.2, 0.1×0.1, ...]
[0.2, 0.1]    ×   [0.2, 0.1, 0.3, 0.0]    =  (4×4 的矩阵，但秩只有 2)
[0.0, 0.2]        [0.4, 0.2, 0.1, 0.3]
[0.3, 0.0]

A 有 8 个数 + B 有 8 个数 = 16 个可训练参数
vs 直接改 ΔW 需要 16 个参数

对于真正的 4096×4096：
A 有 4096×8=32K + B 有 8×4096=32K = 64K 参数 vs 直接改要 1600 万参数
```

### 训练时具体流程

```text
① 加载预训练模型
② 把所有参数设为"不可训练"（requires_grad=False）
③ 在注意力层旁边插入 A 和 B 矩阵
   - A 初始化为随机数
   - B 初始化为全 0（这样 A·B=0，一开始 LoRA 不改变原模型行为）
④ 只训练 A 和 B
⑤ 训练完成后保存 A 和 B
⑥ 推理时把 A·B 算出来加到 W 上：W' = W + A·B
   从此推理和正常模型完全一样，没有任何额外开销
```

### 为什么 B 初始化为 0

如果不初始化为 0，A·B 会是一个随机的矩阵。训练开始的那一刻，模型的行为会突变——因为突然多了一个加在 W 上的随机扰动。

B=0 → A·B=0 → 初始状态下 y=Wx+0=Wx，模型行为不变。然后通过训练，A 和 B 慢慢学到合适的值。

## 八、QLoRA 做了什么（展开讲）

QLoRA = LoRA + 量化。量化的意思是"用更少的比特数存储同一个数"。

### 正常存储 vs 量化

```text
正常（FP16）：每个参数用 16 个比特（2 字节）存储
  - 优势：精度高（能表示 0.001953125 这样的小数）
  - 代价：7B 模型 = 14GB 显存

量化（INT4）：每个参数用 4 个比特（0.5 字节）存储
  - 优势：省空间，7B 模型 = 3.5GB 显存
  - 代价：精度低（只能区分 16 个值）
```

### 量化是怎么做的

```text
原始值（FP16）：     [-1.83, 0.42, -0.15, 3.56, 0.78, -2.11, ...]

找到最大值 3.56 和最小值 -2.11
把区间 [-2.11, 3.56] 均匀分成 16 份（4-bit = 16 个离散值）

量化后（INT4）：     [2, 9, 7, 15, 10, 1, ...]
  -1.83 落到区间第 2 份 → 存成 2
  0.42 落到区间第 9 份 → 存成 9

反量化时：用 0~15 映射回原区间近似值
  2 → -2.11 + 2×(5.67/15) = -1.35（近似 -1.83，有误差）
```

### NF4 为什么比普通量化好

普通量化按均匀分桶。但模型的权重是**正态分布**——大部分值集中在 0 附近，极端值很少：

```text
权重的分布：
      ██
     ████
    ██████       ← 大部分值集中在 0 附近
   ████████
  ██████████
██████████████    ← 极端值很少
-3  -2  -1   0   1   2   3
```

普通量化把 -3 到 3 均匀分成 16 份：

```text
|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|
```

结果：0 附近（数据最多的地方）也只有几个桶，浪费了精度。两端（数据极少的地方）也只有几个桶，更浪费。

NF4（NormFloat4）按分布密度分桶：

```text
|·|·|··|··|···|···|····|····|····|····|···|···|··|··|·|·|
  两端分得宽            中间分得密            两端分得宽
```

数据密集的地方（0 附近）桶多、分得细、精度高。数据稀疏的地方（两端）桶少、分得粗。信息损失比均匀量化少得多。

## 九、微调全流程（实操视角）

### 第 1 步：明确你为什么要微调

| 你的需求 | 要不要微调 |
|----------|:----------:|
| "用 JSON 格式输出" | ❌ Prompt 够 |
| "按我们公司的模板回复" | ✅ 需要微调 |
| "能识别我们的内部术语" | ✅ 需要微调 |
| "客服语气像真人而不是机器人" | ✅ 需要微调 |

核心判断：**风格 + 领域知识** 需要微调；**格式要求** 用 Prompt 就行。

### 第 2 步：准备数据

这是最费时间的环节。把你的业务数据整理成统一格式：

```json
{
  "instruction": "你要模型完成什么任务",
  "input": "用户的实际输入",
  "output": "你期望模型给出的回答"
}
```

**例子**：

```json
{
  "instruction": "用客服身份回复用户的物流查询",
  "input": "我的包裹 EXP_504 三天没更新了",
  "output": "亲，您的包裹在分拣中心暂留，我们已催促仓库加急处理，预计今天下午更新物流信息。给您带来不便非常抱歉！"
}
```

**关键**：output 必须是你在生产环境中**真正希望看到的回答**。不要敷衍，不要用"好的我帮您查"这种废话——模型会学到敷衍。

### 第 3 步：选基座模型

| 用途 | 推荐 | 为什么 |
|------|------|--------|
| 中文客服/对话 | Qwen 2.5/3 | 中文最强 |
| 代码 | CodeQwen / DeepSeek-Coder | 代码专项训练 |
| 英文为主 | Llama 3 / Mistral | 英文生态最好 |
| 你的 M2 Mac | Qwen-1.8B / Qwen-7B QLoRA | 16GB 能跑 |

### 第 4 步：选微调方法

```text
你的显卡是什么？
  ├── 多张 A100/H100 → 全量微调
  ├── 单张 24GB (3090/4090) → LoRA, r=16
  ├── 单张 8~12GB (3060/4060) → QLoRA, r=8
  └── Mac M2 16GB → QLoRA, r=8，或者用 MLX 框架
```

### 第 5 步：训练

用 Llama-Factory（推荐新手）：打开 Web UI → 选模型 → 上传数据 → 设参数 → 点开始。

不需要写代码。训练过程通常 1~4 小时。

### 第 6 步：测试

训练完后，用 20 条真实 case 手动测试：

- 输出格式一致吗？
- 有没有胡言乱语？
- 微调前答错的问题，现在答对了吗？
- 微调前答对的问题，现在还能答对吗？（检验灾难性遗忘）

## 十一、常见误区

### "微调越多越好"

错。数据量不需要很大，质量比数量重要。500 条高质量数据 > 5000 条脏数据。

### "微调能学会一切"

微调不是魔法。微调学的是**风格和格式**，不是海量的新知识。新知识还是要靠 RAG。

### "微调完就能上线了"

微调只是调了参数。你还需要测试、转换格式、部署服务。微调是流程的第一步，不是最后一步。

### "所有参数都能微调"

用 LoRA/QLoRA 时，大部分参数是冻结的。只有一小部分（0.1%~1%）在训练。这不是缺点——这正是它高效的原因。
